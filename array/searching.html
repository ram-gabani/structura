How Computers Find Items: Searching Algorithms

Searching algorithms check for and retrieve an element from a data structure. Based on the search mechanism, algorithms fall into two broad categories: Sequential Search (checking one-by-one) and Interval Search (repeatedly halving a sorted space).

Sequential Search
Linear Scan
Works on any arbitrary unsorted list by inspecting slots sequentially one by one.
Interval Search
Binary Split
Requires pre-sorted data to repeatedly halve the remaining search space.
Speed Delta
50,000× Faster
Searching 1 million sorted items takes at most 20 comparisons vs 1,000,000!

1. Linear Search: Sequential Element Check

Checks every single element from left to right until target is found or list ends

🔍 Sequential Scan

🔑 Real-Life Metaphor:

Imagine searching for your house key in a messy pocket. You pull out item #1, check it. Not it? You pull out item #2, check it. You continue in a straight line until you find the match!

Algorithm Idea:

Iterate from index 0 to N-1. If arr[i] == target, return i. If loop completes without match, return -1.

Iterative
Time: O(n) • Space: O(1)
Single loop inspects items sequentially from 0 to n-1 with zero extra allocations.
Recursive
Time: O(n) • Space: O(n)
Each recursive call frame adds 1 stack frame until the base case or item match is reached.
Ideal Use Case
Unordered Data
Best for unsorted arrays, small collections, and singly linked lists where random access is impossible.

2. Binary Search: Interval Halving Split

How computers locate targets among millions of items in a flash

✂️ Half-by-Half Split

📖 Real-Life Metaphor:

Imagine looking up the word "Penguin" in a 1,000-page English Dictionary. You don't read from page 1. Instead, you open the dictionary in the exact middle (Page 500: Letter "M"). Since "P" comes after "M", you instantly throw away pages 1 to 500 and repeat on the right half!

⚠️ The Golden Rule:

Binary Search ONLY works if the array is already sorted in order.

Binary Search: Find 73 in [10, 20, 30, 40, 50, 73, 90]
1
Middle Element is 40 (Slot [3])
40 < 73 → Discard left half [10, 20, 30, 40]. Set low = mid + 1.
2
Remaining Range: [50, 73, 90]
Middle of remaining is Slot [5] = 73. Found target in just 2 comparisons!
Iterative
Time: O(log n) • Space: O(1)
While low <= high, the range is halved repeatedly with constant extra memory.
Recursive
Time: O(log n) • Space: O(log n)
Divides search space recursively, creating maximum log₂(N) call frames.
Divide & Conquer
Exponential Speedup
Searching 1 million sorted items takes a maximum of only 20 comparisons!

C Implementation: Binary Search

How to write clean, bug-free binary search code in C

📄 binary_search.c 
#include <stdio.h>

// Returns index if target found, otherwise -1
int binarySearch(int arr[], int size, int target) {
    int low = 0;
    int high = size - 1;

    while (low <= high) {
        // Calculate safe mid to avoid integer overflow
        int mid = low + (high - low) / 2;

        if (arr[mid] == target) {
            return mid; // Match found!
        }
        else if (arr[mid] < target) {
            low = mid + 1;  // Target in right half
        }
        else {
            high = mid - 1; // Target in left half
        }
    }
    return -1; // Target not present
}

int main() {
    int sorted_arr[] = {10, 20, 30, 40, 50, 73, 90};
    int n = sizeof(sorted_arr) / sizeof(sorted_arr[0]);
    int target = 73;

    int result = binarySearch(sorted_arr, n, target);

    if (result != -1) {
        printf("Target %d found at slot index: %d\n", target, result);
    } else {
        printf("Target %d not found.\n", target);
    }
    return 0;
}
👨‍🏫 Step-by-Step Breakdown
Line 10: Overflow Protection
Safe Midpoint Arithmetic
Writing low + (high - low) / 2 avoids 32-bit integer overflow that occurs with (low + high) / 2 when handling large index values.
Line 15 & 18: Halving Subarray
Boundary Discard
Setting low = mid + 1 or high = mid - 1 discards half the array in 1 comparison step.
