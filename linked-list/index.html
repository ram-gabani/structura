What is a Linked List?

In an array, elements are locked into contiguous, fixed-size blocks of physical RAM. If your array runs out of space, resizing requires allocating an entire new block and copying every single item!

A Linked List solves this limitation completely. Instead of storing items side-by-side, each element is created individually inside the computer's free memory heap as an independent Node. Each node stores its own data, plus a Pointer that stores the memory address of the next node!

Dynamic Sizing
Grows on Demand
Nodes are allocated one-by-one using malloc() only when needed, with zero wasted pre-allocated capacity.
Non-Contiguous
Scattered in RAM
Nodes live anywhere in memory. They are stitched together exclusively by address pointers stored inside each node.
⚡ O(1) Insert
Zero Shifting
Inserting or deleting at the front requires simply updating pointer addresses without shifting downstream elements.
Sequential Access
No Direct Math
To reach node #5, you cannot calculate an offset. You must traverse from HEAD through nodes 1, 2, 3, and 4.

💡 The Role of the HEAD Pointer
  • The Only Entry Point: The entire linked list is accessed solely through the pointer variable head.
  • Losing HEAD Means Memory Leak: If you overwrite head without saving its address, all nodes become unreachable zombies in memory!
  • Empty List State: When head == NULL, the linked list is verified to be completely empty.

Real-Life Analogy: The Campus Treasure Hunt

How physical clues mirror sequential pointer memory

🗺️ Analogy: Clue Cards in an Envelope

Imagine participating in a campus scavenger hunt. The organizer gives you the first clue card (the HEAD pointer) which directs you to the Library. At the library, you open the envelope: inside is a riddle (Data) and an instruction: "Walk to Canteen Table 4" (the Next Pointer).

Notice two critical rules that match computer science:

  • No Pre-determined Locations: Clues can be anywhere across campus — Library, Canteen, Computer Lab, or Ground. They do not have to be in consecutive rooms (Non-contiguous memory).
  • Strict Sequential Order: You cannot jump straight to Clue #4 because nobody knows where Clue #4 is hidden until they inspect Clue #3! (Sequential Access: O(n)).
  • The Finish Line: The final card says "Congratulations! Hunt Complete." with no further address (The NULL pointer).

Array vs. Linked List: Architectural Comparison

Exam-critical differences in memory, access speed, and allocation

⚖️ Core Trade-offs
Feature Array Linked List Architectural Reason
Memory Layout Contiguous (unbroken sequence) Non-contiguous (scattered in heap) Arrays need 1 continuous block; Nodes use isolated pointers
Size Allocation Static (fixed at compile/declaration) Dynamic (allocates & frees on demand) Linked lists call malloc() per node at runtime
Element Access ⚡ O(1) Instant 🚶 O(n) Sequential Arrays calculate Base + i*size; Lists must follow pointer chain
Insertion at Front 🚶 O(n) Shifting ⚡ O(1) Rewire Arrays must shift all n elements; Lists only update head
Memory Overhead Low (only data stored) Higher (+4 or +8 bytes per node) Every node must store an extra pointer variable (next)
CPU Cache Hit Rate Very High (spatial locality) Lower (scattered addresses) CPUs prefetch neighbor RAM blocks, favoring arrays

Compilable C Program: Creating & Traversing a List

Standard C99 program demonstrating struct declaration, malloc(), and freeing memory

C99 linked_list_intro.c 
#include <stdio.h>
#include <stdlib.h>

/* 1. Define the Self-Referential Node Structure */
struct Node {
    int data;               /* Payload value */
    struct Node *next;      /* Pointer storing address of next node */
};

/* 2. Helper function to create a new dynamically allocated node */
struct Node* createNode(int value) {
    struct Node *newNode = (struct Node*)malloc(sizeof(struct Node));
    if (newNode == NULL) {
        printf("Memory allocation failed!\n");
        exit(1);
    }
    newNode->data = value;
    newNode->next = NULL;   /* Default next to NULL */
    return newNode;
}

/* 3. Helper function to print all nodes sequentially */
void printList(struct Node *head) {
    struct Node *temp = head;
    printf("HEAD -> ");
    while (temp != NULL) {
        printf("[%d | next] -> ", temp->data);
        temp = temp->next;  /* Advance to next node */
    }
    printf("NULL\n");
}

/* 4. Function to free all allocated memory to prevent memory leaks */
void freeList(struct Node *head) {
    struct Node *temp;
    while (head != NULL) {
        temp = head;
        head = head->next;
        free(temp);         /* Return memory block to heap */
    }
}

int main(void) {
    /* Step A: Initialize an empty list */
    struct Node *head = NULL;

    /* Step B: Create three isolated nodes */
    struct Node *first  = createNode(10);
    struct Node *second = createNode(20);
    struct Node *third  = createNode(30);

    /* Step C: Link nodes together via pointers */
    head = first;           /* Head points to node 1 */
    first->next = second;   /* Node 1 points to node 2 */
    second->next = third;   /* Node 2 points to node 3 */
    /* third->next is already NULL */

    /* Step D: Traverse and display the list */
    printList(head);

    /* Step E: Always clean up dynamically allocated memory */
    freeList(head);
    head = NULL;

    return 0;
}
PROGRAM OUTPUT:
HEAD -> [10 | next] -> [20 | next] -> [30 | next] -> NULL

Common Beginner Pitfalls in C Pointers

The 3 most dangerous memory errors every 3rd-semester student must avoid

Pitfall 01 ⚠️
Losing the HEAD Pointer
Using head = head->next inside a display loop permanently destroys your reference to earlier nodes!
❌ while(head) { head=head->next; }
✓ struct Node *temp = head; // use temp
Pitfall 02 ⚠️
Dereferencing NULL
Calling temp->next when temp == NULL triggers an immediate segmentation fault (crash!).
❌ while(temp->next != NULL) // on empty list
✓ if(head == NULL) return;
Pitfall 03 ⚠️
Memory Leaks (No free)
Unlike Python or Java, C has no garbage collector. Failing to call free() leaves memory locked forever.
❌ // Program exits without free()
✓ free(temp); // Return heap bytes
