Binary Search Tree (BST)

A Binary Search Tree is a binary tree structured under a strict relational invariant: for any node, all keys in its left subtree are smaller, and all keys in its right subtree are larger. This property turns searches, insertions, and deletions into high-speed \(O(\log n)\) operations.

1. The BST Ordering Invariant

The golden mathematical rule governing every node

Key Property
For every node X:
• All nodes in LeftSubtree(X) < X.key
• All nodes in RightSubtree(X) > X.key

Because this property applies recursively to every single node down the tree, an In-Order Traversal (Left → Root → Right) of any valid BST is guaranteed to output all keys in strictly ascending sorted order!

2. Search & Insert in C

Binary division of the tree search space

⚡ O(log n) Time
C BST Search Function 
struct TreeNode* search(struct TreeNode *root, int target) {
    /* Base cases: root is null or key is found */
    if (root == NULL || root->data == target) {
        return root;
    }
    /* Target is smaller -> search left */
    if (target < root->data) {
        return search(root->left, target);
    }
    /* Target is larger -> search right */
    return search(root->right, target);
}
C BST Insert Function 
struct TreeNode* insert(struct TreeNode *root, int val) {
    if (root == NULL) {
        return createTreeNode(val);
    }
    if (val < root->data) {
        root->left = insert(root->left, val);
    } else if (val > root->data) {
        root->right = insert(root->right, val);
    }
    return root; /* Return unchanged pointer */
}

3. Node Deletion: The Three Critical Cases

How to preserve the BST property when removing an interior node

Complex Algorithm
Case 1
Leaf Node (0 Children)
Simplest case. Directly deallocate the node with free(node) and return NULL to the parent.
Case 2
One Child (Left or Right)
Bypass the node. Return the non-null child pointer directly to the parent, splicing out the deleted node.
Case 3
Two Children
Find the In-Order Successor (smallest node in right subtree). Copy its data into current node, then delete that successor from the right subtree.
C99 bst_delete.c 
/* Helper: Find node with minimum value in a subtree */
struct TreeNode* findMin(struct TreeNode *node) {
    struct TreeNode *curr = node;
    while (curr && curr->left != NULL) {
        curr = curr->left;
    }
    return curr;
}

/* Delete a node from BST */
struct TreeNode* deleteNode(struct TreeNode *root, int key) {
    if (root == NULL) return root;

    if (key < root->data) {
        root->left = deleteNode(root->left, key);
    } else if (key > root->data) {
        root->right = deleteNode(root->right, key);
    } else {
        /* Node to be deleted found! */

        /* Case 1: No child or Case 2: One child */
        if (root->left == NULL) {
            struct TreeNode *temp = root->right;
            free(root);
            return temp;
        } else if (root->right == NULL) {
            struct TreeNode *temp = root->left;
            free(root);
            return temp;
        }

        /* Case 3: Two children */
        /* Get In-Order Successor (smallest in right subtree) */
        struct TreeNode *temp = findMin(root->right);
        root->data = temp->data; /* Copy value */
        /* Delete the successor */
        root->right = deleteNode(root->right, temp->data);
    }
    return root;
}

BST Performance Complexity

Average case vs worst case skewed degradation

Operation Average Case (Balanced Tree) Worst Case (Skewed Tree) Why the difference exists
Search 🚀 O(log n) 🚶 O(n) Balanced trees halve height each level; Skewed trees become linear chains
Insert 🚀 O(log n) 🚶 O(n) Requires descending to leaf level
Delete 🚀 O(log n) 🚶 O(n) Search cost + successor lookup
