Challenge 1: Reverse a String using Stack

LIFO Reversal

Given a string (e.g. "ANTIGRAVITY"), reverse its characters in-place using a character stack.

💡 Reveal Push-and-Pop Algorithm & C Solution

Mechanism: Push all characters onto the stack sequentially from index 0 to n-1. Then pop them one-by-one back into the string. Because a stack is LIFO, the characters naturally emerge reversed! 

#include <string.h>

void reverseString(char *str) {
    int n = strlen(str);
    char stack[100];
    int top = -1;

    /* Push all chars */
    for (int i = 0; i < n; i++) {
        stack[++top] = str[i];
    }
    /* Pop back into original string */
    for (int i = 0; i < n; i++) {
        str[i] = stack[top--];
    }
}

Challenge 2: Implement Two Stacks in a Single Array

Memory Optimization

How can you implement two independent stacks in an array of size MAX such that neither stack overflows unless the total number of elements exceeds MAX?

💡 Reveal Opposite Ends Technique & C Solution

Strategy: Start Stack 1 from the leftmost slot (top1 = -1) and grow rightwards. Start Stack 2 from the rightmost slot (top2 = MAX) and grow leftwards. Overflow occurs only when top1 + 1 == top2! 

struct TwoStacks {
    int arr[100];
    int top1;
    int top2;
};

void initTwoStacks(struct TwoStacks *ts) {
    ts->top1 = -1;
    ts->top2 = 100;
}

void push1(struct TwoStacks *ts, int x) {
    if (ts->top1 < ts->top2 - 1) {
        ts->arr[++(ts->top1)] = x;
    } else {
        printf("Stack 1 Overflow!\n");
    }
}

void push2(struct TwoStacks *ts, int x) {
    if (ts->top1 < ts->top2 - 1) {
        ts->arr[--(ts->top2)] = x;
    } else {
        printf("Stack 2 Overflow!\n");
    }
}

2. Common Stack Bugs in C

Avoid these 3 common mistakes in laboratory practical examinations

Pitfall 01
Popping Without Underflow Check
Calling stack[top--] when top == -1 reads stack[-1] (illegal negative array indexing)!
Pitfall 02
Off-by-One Full Condition
An array of size MAX has valid indices up to MAX - 1. Checking top == MAX allows one extra push and corrupts memory!
Pitfall 03
Peek Decrementing Top
Accidentally using top-- inside peek() inadvertently destroys the topmost element instead of just inspecting it.
