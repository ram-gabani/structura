Core Applications of the Stack

Stacks are not merely academic constructs; they power the internal execution engine of every operating system and compiler on Earth. Explore how the Call Stack handles recursion, how compilers validate syntax, and how arithmetic expressions are calculated.

1. The Function-Call Stack & Recursion

How CPUs keep track of active function calls and local variables

OS Architecture

Whenever a function is invoked in C, the operating system creates an Activation Record (Stack Frame) containing the function's arguments, local variables, and the return instruction address. This frame is pushed onto the CPU's hardware call stack.

Tracing Recursive Factorial: fact(3)
Frame 1: main() • calls fact(3)
Frame 2: fact(n = 3) • waits for fact(2)
Frame 3: fact(n = 2) • waits for fact(1)
Frame 4: fact(n = 1) ← BASE CASE! Returns 1 & POPS
💡 Why Infinite Recursion Crashes Programs

If a recursive function lacks a base case, it pushes stack frames endlessly until it exhausts the memory allocated to the program's call stack. This results in the infamous Stack Overflow segmentation crash!

2. Parentheses & Bracket Matching

How compilers and code editors verify syntax balance

Compiler Logic

To determine whether an expression like { [ ( a + b ) * c ] } has balanced brackets:

  1. Scan the string character-by-character from left to right.
  2. If an opening bracket ((, {, [) is found, PUSH it onto the stack.
  3. If a closing bracket (), }, ]) is found:
    • If the stack is empty, return Unbalanced (closing bracket with no opener!).
    • Otherwise, POP the top bracket and verify if it matches the current closing bracket type. If mismatch, return Unbalanced.
  4. At string end: If the stack is completely empty, the expression is Balanced!
C Balanced Parentheses Checker 
int isMatchingPair(char open, char close) {
    if (open == '(' && close == ')') return 1;
    if (open == '{' && close == '}') return 1;
    if (open == '[' && close == ']') return 1;
    return 0;
}

int isBalanced(const char *expr) {
    char stack[100];
    int top = -1;

    for (int i = 0; expr[i] != '\0'; i++) {
        char ch = expr[i];
        if (ch == '(' || ch == '{' || ch == '[') {
            stack[++top] = ch; /* Push */
        } else if (ch == ')' || ch == '}' || ch == ']') {
            if (top == -1) return 0; /* Unmatched closing */
            char open = stack[top--]; /* Pop */
            if (!isMatchingPair(open, ch)) return 0; /* Mismatch */
        }
    }
    return (top == -1); /* Balanced if stack is empty */
}

3. Expression Notations: Infix, Postfix & Prefix

Why computers evaluate expressions without operator precedence ambiguity

Notation Operator Position Example Computer Usage
Infix Between operands (A + B) (A + B) * C Human-readable; requires parenthesis rules & BODMAS
Postfix (RPN) After operands (A B +) A B + C * Ideal for CPUs: evaluated left-to-right using a single stack
Prefix (Polish) Before operands (+ A B) * + A B C Evaluated right-to-left using a stack

Evaluating Postfix Expression: 5 3 + 2 *

Algorithm: Scan tokens left to right. When an operand is encountered, push it onto the stack. When an operator is encountered, pop the top two operands, apply the operator, and push the result back!

1. Token '5' → Push 5 → Stack: [5]
2. Token '3' → Push 3 → Stack: [5, 3]
3. Token '+' → Pop 3, Pop 5 → Compute 5 + 3 = 8 → Push 8 → Stack: [8]
4. Token '2' → Push 2 → Stack: [8, 2]
5. Token '*' → Pop 2, Pop 8 → Compute 8 * 2 = 16 → Push 16 → Stack: [16]
Final Result: 16 (Popped from stack)
